# Spec: AI Project Notebook v0.1

## 1. 要解决什么问题

用户拿到一个陌生项目后，需要理解它的结构、模块、命令和数据流。v0.1 提供一个命令行工具，帮助用户**初始化项目知识地图**、**填写笔记**、**查阅/搜索笔记**、**导出报告**，把理解结果沉淀为可维护的 Markdown 文档。

v0.1 不自动分析代码。所有模块笔记和职责说明由用户手工填写。

## 2. 版本目标

一个最小命令行工具集，包含 4 个脚本 + 1 个已有脚本，覆盖从初始化到导出报告的完整流程。

## 3. 功能清单

### 本版本实现

| # | 功能 | MVP 描述 | 验收标准 |
| ---- | ---- | ---- | ---- |
| 1 | 初始化项目地图 | `init_project.py <目标路径>` — 复制 harness 骨架目录到目标项目，并自动扫描目标项目已有目录结构填入 `directory-map.md` | 执行后目标路径下出现完整 harness 目录；`directory-map.md` 包含目标项目的目录树 |
| 2 | 填写模块笔记 | 用户手工编辑 `module-map.md` 表格，登记模块名称、文件路径、职责、依赖 | `module-map.md` 包含模板表格，格式正确 |
| 3 | 查看笔记 | 用户用 `cat` 或编辑器直接读取 `project-map/` 下任意文件 | 文件可读、格式正确 |
| 4 | 搜索笔记 | `search_notes.py "关键词"` — 在 `project-map/` 和 `feedback/` 中搜索关键词，输出匹配行及所在文件 | 搜索结果包含文件名和匹配行 |
| 5 | 导出报告 | `export_report.py` — 合并 project-map 下所有 `.md` 文件，输出带项目名、时间戳的格式化报告 | 报告包含标题头、所有文件内容按序排列、每段有文件来源 |
| 6 | 验证结构完整 | `check_structure.py` — 检查关键目录和文件是否存在 | 已有，列出缺失项，全部通过返回 0 |
| 7 | 帮助 | `help.py` — 打印所有可用命令和一句话用途 | 列出全部命令名称和功能说明 |

### 暂不实现

- 自动分析代码
- 项目地图自动更新
- 统一 CLI 入口（`project-notebook` 命令）
- Web 前端、数据库、向量检索、大模型 API、多 Agent 运行时

## 4. 风险与未决问题

- `init_project.py` 扫描目录时，目标项目可能有大量无关文件（node_modules、.git 等），需要默认排除常见目录
- `search_notes.py` 依赖系统 grep，Windows 下 grep 可能不可用，需用 Python 标准库实现搜索避免依赖
- 4 个脚本分散在 `harness/scripts/` 下，用户需要记住多个命令名——`help.py` 缓解但不能根除，v0.2 应考虑统一 CLI 入口
