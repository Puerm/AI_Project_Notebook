# Spec: v0.2 — Harness 部署范围修正 + 工作流系统部署

## 1. 要解决什么问题

v0.1 的 `init_project.py` 把两类不该部署的东西混入了目标项目：安装器自身（`init_project.py`）在目标项目里没有用；而目标项目真正需要的 AI 辅助开发能力（`.claude/` 下的 agent 定义、workflow 命令）却没有部署过去。

## 2. 版本目标

修正部署清单，让目标项目获得完整的 harness 工具 + AI 工作流能力。

## 3. 功能清单

### 本版本实现

| # | 功能 | MVP 描述 | 验收标准 |
| ---- | ---- | ---- | ---- |
| 1 | `init_project.py` 不部署到目标项目 | 拷贝 harness 后删除目标项目中的 `init_project.py` | 目标项目的 `harness/scripts/` 下不含 `init_project.py` |
| 2 | `.claude/agents/` 部署到目标项目 | 全部 7 个 agent 定义文件随 `init_project` 拷贝到目标项目 | 目标项目 `.claude/agents/` 下含 7 个 agent `.md` 文件 |
| 3 | `.claude/commands/` 部署到目标项目 | 全部 5 个命令入口随 `init_project` 拷贝到目标项目 | 目标项目 `.claude/commands/` 下含 workflow 和 pm 子目录 |
| 4 | `.claude/skills/` 部署到目标项目 | 空 skills 目录随 `init_project` 创建 | 目标项目 `.claude/skills/` 存在且为空（或仅含 README） |
| 5 | `check_structure.py` 检查 `.claude/` 完整性 | `.claude/agents/`、`.claude/commands/`、`.claude/skills/` 加回检查清单，与部署行为一致 | Notebook 自身和 BioTec 项目均 PASS |

### 暂不实现

- agent 定义的通用化改造（当前 agent 约束保留项目特定内容，后续再抽离）
- 目标项目已有的 `.claude/` 内容与 harness 部署内容的冲突处理

## 4. 风险与未决问题

- `.claude/agents/` 中的 agent 定义包含 Notebook 项目的版本约束（如"不引入超出 v0.1 范围的假设"），部署到其他项目后可能不适用。本次不改 agent 定义，后续版本处理。
- 目标项目可能已有自己的 `.claude/` 配置（如 BioTec 有 `settings.local.json`），覆盖时需保留已有文件。
