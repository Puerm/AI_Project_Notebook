# Spec: 修复维度分析 Prompt 溢出

## 1. 要解决什么问题

`analyze_project.py --digest` 的聚焦三维度分析（架构/用户故事/风险）中，`format_files_for_llm` 将筛选后的文件完整内容无截断地拼入 LLM prompt。当目标项目较大时（如风险分析筛选出 323 个文件），prompt 超过模型 1M token 上下文限制，HTTP 400 永久失败。同时 `_call_llm_with_retry` 对 HTTP 400 硬错误做无意义重试（3 次指数退避），浪费用户时间。

## 2. 版本目标

三个聚焦维度分析在任何项目规模下都不会因 prompt 过大而 HTTP 400 失败。超大输入自动截断降级，硬错误不再重试。

## 3. 功能清单

### 本版本实现

| 功能 | MVP 描述 | 验收标准 |
| ---- | -------- | -------- |
| prompt token 预算控制 | `format_files_for_llm` 或调用处增加 token 上限（预留模型上下文的 80%），超出时按文件优先级截断 | 323 个风险文件的场景不再 400 失败；截断后在降级输出中标注被截断的文件列表 |
| filter 文件数上限 | 三个 filter 函数各加上限（如架构 100、用户故事 150、风险 200），超出按优先级排序截断 | 筛选结果不会无限膨胀 |
| retry 跳过硬错误 | `_call_llm_with_retry` 遇到 HTTP 400 立即降级，不重试 | HTTP 400 时 0 次重试，直接返回降级结果 |

### 暂不实现

- 不在 digest 收集阶段做 token 控制（digest 文件池本身不做 LLM 调用）
- 不修改非 digest 路径（基础分析的文件量通常不会溢出）

## 4. 风险与未决问题

- **截断可能丢失关键风险信号**：风险分析最敏感，截断后可能漏掉真正重要的安全问题。缓解：按文件优先级排序，配置文件 > 脚本文件 > 安全关键词匹配，确保高风险文件优先保留
- **80% 阈值是否合理**：不同模型的上下文窗口不同，需从 API 响应中动态获取或配置化
