# Spec: Harness 框架通用化

## 1. 要解决什么问题

当前 harness 框架与 AI Project Notebook 项目深度耦合，无法干净地部署到其他项目。具体表现为三类硬编码：

- **名称/版本硬编码** — `help.py` 写死 "AI Project Notebook v0.5.1"，`diagnosis.txt` 写死 "Harness 自我升级系统"
- **语言/工具链假设** — agent 定义和规则文件中假设目标项目一定是 Python + pytest
- **路径结构耦合** — `app/analyzer/` 应用代码混在 harness 目录内，`check_structure.py` 包含 38 个硬编码文件路径

目标：将 harness 抽取为纯框架目录，消除项目特定的硬编码内容，使 `init_project.py` 部署到新项目时能根据目标项目特征自动填充模板变量。

## 2. 版本目标

Harness 框架通用化 v0.1 — 消除 AI Project Notebook 特定内容，建立模板变量系统，实现基于 LLM 项目检测的自动部署。

分两步走，本版本为第一步：**机械层面的通用化**。第二步（后续版本）实现 LLM 深度语义适配。

## 3. 功能清单

### 本版本实现

| 功能 | MVP 描述 | 验收标准 |
| ---- | -------- | -------- |
| 1. 模板变量系统 | 新建 `harness/config/project.yaml` 作为所有模板变量的单一来源；字段：`project_name`、`languages`（列表）、`test_framework`、`package_manager` 等；其他文件通过占位符 `{{project_name}}` 引用 | project.yaml schema 清晰；占位符替换逻辑正确；缺字段时有合理默认值 |
| 2. agent 定义通用化 | `generator.md` 和 `tester.md` 移除 Python/pytest 硬编码，改为引用 `{{test_command}}` 等占位符；语义级适配（如根据目标语言重写具体规则）留给第二步 | agent 文件中不再出现 "python"、"pytest"、"snake_case.py" 等 Python 特定词汇；占位符在部署时正确填充 |
| 3. 规则文件通用化 | `coding-rules.md` 移除所有语言特定示例（如 "Python 用 snake_case.py"、"python -m pytest"），只保留语言无关的通用约束（如"命名遵循项目约定"、"修改后运行测试"）；具体语言规范留给第二步 LLM 补充 | 规则文件中不再出现任何特定语言的语法或工具名称；规则约束对任意语言项目适用 |
| 4. 目录结构分离 | `app/analyzer/` 目录和 `harness/scripts/analyze_project.py` 移至项目根层级（`app/`），与 harness 框架目录分离；harness 成为纯框架目录不含应用代码 | harness 目录下不再包含 `app/` 子目录；analyze_project.py 不再属于 harness/scripts/；`check_structure.py` 中对应的检查项同步移除 |
| 5. 清理 check_structure.py | 从 agent 定义（generator/reviewer/harness_maintainer）、workflow 编排指令（4 个 command 文件）、diagnose_and_fix.py 中移除所有对 `check_structure.py` 的引用和调用 | 所有文件中不再出现 `check_structure.py`；沙盒验证步骤从三步（check_structure + pytest + agent YAML）调整为两步（pytest + agent YAML）；agent 启动流程中移除"运行 check_structure.py"步骤 |
| 6. init_project.py LLM 增强 | 部署时 LLM 扫描目标项目：文件后缀统计 → 语言列表、配置文件检测（package.json / pyproject.toml / go.mod / Cargo.toml 等）→ 包管理器/测试框架/入口文件；输出 `project.yaml`；复制 harness 骨架后对所有含占位符的文件执行模板填充 | LLM 能正确识别 Python/JS/Go/Rust/TypeScript 项目；project.yaml 字段完整；占位符替换后文件内容正确；LLM 不可用时降级为纯静态检测（CLI 参数 + 文件后缀扫描） |
| 7. 文档同步 | 更新 `harness/project-map/` 下 5 个文档（overview/directory-map/module-map/command-map/data-flow）+ change-map 登记本次变更 | 所有文档反映新的目录结构和模块职责 |

### 暂不实现

- LLM 深度语义适配（根据目标项目语言/框架重写规则文件和 agent 定义的具体内容）
- 修改 `harness/state/` 下 Python 源文件的自测代码（feedback_engine.py、workflow_state.py 中写死的 agent 名称）
- 跨项目知识迁移
- 部署后的自动验证

## 4. 风险与未决问题

- **analyze_project.py 迁移影响** — 移出 harness 后，analyze_project.py 的 import 路径需要调整，`check_structure.py` 的检查项需要同步移除。需确认 `harness/scripts/` 下其他脚本是否也依赖 `app.analyzer`
- **占位符语法冲突** — `{{}}` 可能与 YAML/Markdown 现有语法冲突，需确认模板引擎选择（Python string.Template vs Jinja2 轻量模板）
- **LLM 项目检测准确率** — 多语言混合项目或非标准目录结构的项目可能导致误判。缓解：LLM 不可用时降级为纯静态检测
- **harness/state/ Python 文件的自测代码** — 包含 `explorer-blocked`、`tester-failed` 等 agent 特定名称，本版本不处理，可能在新项目中运行自测时产生噪音
