# Spec: v0.3 智能项目分析引擎

## 1. 要解决什么问题

v0.1 的 `init_project.py` 只复制空模板到目标项目的 `harness/project-map/`，用户拿到的是空壳，无法真正理解项目。v0.2 加固了工作流框架但仍未填补这一缺口。

v0.3 提供自动化的项目分析能力：扫描目标项目代码，自动填写 project-map 文件，让用户（或后续 Agent）获得项目结构、模块职责、数据流向的清晰认知。

## 2. 版本目标

新增 `analyze_project.py` 命令，自动分析 Python + JS/TS 项目，生成 `overview.md`、`directory-map.md`、`module-map.md`、`data-flow.md` 四个 project-map 文件。

## 3. 功能清单

### 本版本实现

| 功能 | MVP 描述 | 验收标准 |
| ---- | -------- | -------- |
| `analyze_project.py` 命令 | 新命令，手动触发项目分析 | 运行后生成/更新 4 个 project-map 文件 |
| **混合分析架构** | 结构层硬编码（目录扫描、import 关系、函数/类提取）+ 语义层 LLM 辅助（模块描述、项目概述、目录标注） | 硬编码部分秒级完成；LLM 部分可选启用，不可用时降级到模板描述 |
| **overview.md 自动生成** | 一句话项目描述 + 技术栈识别 + 入口文件检测 + 项目类型推断 | 能正确识别常见框架（Express/Next/React/Flask 等）和项目类型（Web/CLI/库） |
| **directory-map.md 自动标注** | 目录树 + 每个目录的用途标注 | `src/` 标注为"源代码"、`tests/` 标注为"测试"，非标准目录名通过内容推断 |
| **module-map.md 中粒度分析** | 每个文件 → 模块描述 + 主要函数/类列表 + 各自的一句话职责 | Python 通过 AST 解析，JS/TS 通过第三方解析器解析，精度一致 |
| **data-flow.md 模块级依赖** | 标注哪个模块 import 了哪个模块 | 生成模块间依赖关系图，Python 和 JS/TS 均支持 |
| **JS/TS 解析器自动管理** | 检测到 JS/TS 项目时检查第三方解析器（esprima/acorn）是否可用，不可用则提示并帮助安装 | 用户执行 `analyze_project.py` 时自动检测→提示→安装，无需手动操作 |
| **LLM 可选降级** | LLM 不可用时自动降级为纯硬编码模式，输出标注精度有限 | 无论是否连接 LLM，命令都能跑完，不会崩溃 |

### 暂不实现

| 功能 | 说明 |
| ---- | ---- |
| command-map 自动生成 | 留到 v0.4+ |
| change-map 自动填充 | 留到 v0.4+ |
| 细粒度 module-map（函数签名、参数、继承关系、依赖图） | 留到 v0.4+ |
| 模块级以上 data-flow（数据传递链、输入输出类型） | 留到 v0.4+ |
| Python + JS/TS 以外的语言支持 | 留到 v0.4+，面向多语言通用框架 |
| 不同项目类型的适配分析重点（Web→路由、库→公开 API、CLI→命令入口） | 留到 v0.4+ |
| 增量分析（文件变更时只重新分析变更部分） | 留到后续版本 |

## 4. 风险与未决问题

| 风险/问题 | 处理策略 |
| --------- | -------- |
| LLM API 的配置方式 | 未决 — 用环境变量？config 文件？需实现时讨论 |
| LLM 提示词的质量直接决定语义分析结果 | 需在实现阶段反复调优 |
| JS/TS 解析器（esprima/acorn）的具体选型 | 未决 — Planner 和 Explorer 评估后决定 |
| 大型项目的分析性能和 LLM token 消耗 | 需 Explorer 在设计前侦察项目规模上限 |
