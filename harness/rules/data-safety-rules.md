# Data Safety Rules

可执行的数据安全规则。每条规则必须可检查。

## 目录保护

1. 不得删除 `data/` 目录下的任何用户数据文件
2. 不得以任何理由清空 `data/` 目录
3. 批量操作（如 `rm -rf`）必须以 `harness/` 或 `app/` 为起点，禁止以项目根目录为起点

## 文件操作

4. 覆盖已有文件前必须先确认用户意图，不得静默覆盖 `data/` 下的文件
5. 移动 `data/` 下的文件前必须确认目标路径也在 `data/` 内
6. 任何脚本在执行文件删除操作时必须先输出将要删除的文件列表，等待确认

## 数据格式

7. `data/` 下的数据文件必须使用 UTF-8 编码
8. 写入文件必须使用原子写入：先写临时文件，写入成功后再 rename
9. 读取外部输入（用户参数、文件内容）时必须验证格式，不合法则拒绝并报告

## 敏感信息

10. 不得将 API Key、Token、密码写入任何会被 git 跟踪的文件
11. 检查 `.gitignore` 是否包含 `.env`、`*.key`、`credentials.*`
12. 提交前运行 `git status` 确认没有误提交敏感文件
