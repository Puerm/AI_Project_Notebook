# 分析维度
请从以下维度逐一分析：

## 1. 核心用户故事
按照标准用户故事格式（作为 <角色>，我想要 <目标>，以便 <价值>）列出主要用户故事。按业务优先级排列，从最重要的开始。每个故事必须附上代码证据（文件名和关键代码片段）。

## 2. 角色识别
从路由、权限控制、API 接口等代码中识别出项目的用户角色（如普通用户、管理员、第三方调用方等），列出每个角色的特征证据。

## 3. 功能模块映射
将每个用户故事映射到对应的代码模块和 API 端点。使用表格呈现：故事 / 角色 / 模块路径 / HTTP 端点（如适用）/ 证据。

## 4. 故事依赖关系
描述用户故事之间的先后顺序和依赖关系（如用户注册 -> 用户登录 -> 核心操作），说明哪些故事是后续功能的前置条件。

## 5. 技术支持故事
识别非功能性需求对应的故事，涵盖：性能优化、安全加固、可维护性提升、错误处理完善等。

## 6. 功能覆盖度评估
评估当前代码库实现了哪些典型功能，缺失了哪些常见功能（如缺少密码重置、缺少日志记录等）。

# 输出约束
- 输出完整的 Markdown 文档，以 # 标题开始
- 每个故事必须有代码文件路径作为证据
- 如果已有架构分析文档，将其作为上下文参考
- 不确定的功能在句末标注 [推测]
- 使用中文编写
